The machine-readable current-run record is [oda-pilot-2026-09-27.json](oda-pilot-2026-09-27.json); `run_oda_pilot.py` can rerun the same five-source check. A separate second conversion confirmed all five outputs had **different whole-file SHA-256 hashes**. Pairwise comparison localized the changes to two `HEADER` variables, `$TDUPDATE` and `$TDUUPDATE`; `BLOCKS`, `CLASSES`, `ENTITIES`, `OBJECTS`, `TABLES`, and other present non-header sections were identical between those two runs. Two files changed output length by one byte because the timestamp's decimal spelling changed. This means conversion is **not byte-deterministic** across runs, although the drawing sections matched in this pilot. Freeze and hash one output set for all benchmark arms; do not regenerate each arm separately.

This also exposes a spec gap: v1.1's cheap-normalization arm A2 names `$TDUPDATE` but omits `$TDUUPDATE`, which the converter also changes. Amend the pre-freeze spec or explicitly count that value in undo data before A2/A3 comparisons.

## Remaining pilot checks

- A parser check establishes DXF syntax and entity presence, **not geometric fidelity**. Compare representative converted drawings with their sources in a CAD viewer or another trusted read path before accepting R2018 as the full-batch format. Pay particular attention to proxy/custom objects and the R2007/R2018 inputs.
- The five pilots expanded 2.03 MB of DWG input to about 8.52 MB of DXF output. This suggests the 47-file batch will need materially more space than the 44.5 MB source corpus. Recheck free space and use a guarded batch directory before conversion.
- All 49 source files still matched the Step 1 hash manifest after the pilot.

**Step 2 status:** command-line conversion and structural checks passed for all five version groups. Visual/content fidelity is not yet established, so output-version selection remains provisional and no Tier B corpus is frozen.
