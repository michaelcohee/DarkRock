# Frozen C2 hybrid follow-up

Freeze this document and `run_c2_hybrid_v4.py` before generating `darkrock-cad-dxf-v4 --split test`. The existing C2-name, C2-sketch, C2-key, C2-name+key, and C2-0 rules remain as recorded in `c2-base-selection-freeze.md`; the **only new arm** is C2-hybrid.

**Hybrid:** for each unique file, consider (a) the first already-stored unique file in its declared name family, if any, and (b) the single already-stored unique file with the greatest positive overlap in its set of frozen A3 v2 geometry keys. Break key-score ties by prior path order. If both choices name the same base, attempt it once. Try at most two `zstd -3 --patch-from` patches. Decode each attempted patch against its base, compare bytes and SHA-256 to the source, and count a failed verification as a miss. Select the smallest verified patch, breaking equal-size ties by prior path order. Store it only when it is at least **1,024 bytes** smaller than standalone `zstd -3`; otherwise store standalone. Exact duplicates reference an earlier byte-identical file. Base candidates are earlier stored unique files only; files are processed in path order. No transform/edit path is created.

Run the new test-only v4 split in a single generation → verification → comparison invocation after the freeze commit. Run the same arms on the 47 converted DXFs separately, labelled **exploratory** because they have already been used to compare pickers. Every result uses the existing complete-ledger RedTail-X variable-tail 4+2 accounting and all 21 one/two-share loss checks. No pooled percentages.

**Diagnostics:** the proposal funnel for C2-key and C2-sketch counts each candidate patch attempt once. Categories are verify failure, patch no smaller than standalone, valid but below the 1,024-byte gain, valid and competitive but not selected, and accepted winner. These disjoint categories sum to proposals. Sidecar timing is wall time: key-build time includes the calls to the frozen Rust `geometry_keys` extractor plus constructing Python sets from its output, while total encode time is feature extraction plus standalone compression plus the C2-key ledger build/verification and 4+2 measurement, excluding the later diagnostic replay. Key-set memory is the Python set and unique string payloads measured with `sys.getsizeof`. Peak RAM is worker-process `ru_maxrss`, separately measured per corpus; it includes the Python and native allocator in that process, but not peak RSS of short-lived zstd/Rust children. These are sidecar costs, never protected bytes.

The real-file concentration follow-up reads the existing `c2-base-selection-v3-results.json` choices only. Per-file savings are **selected payload bytes**, not independently allocated protected bytes; physical 4+2 savings are reported at the complete-ledger level. Top-1/3/5 shares use the *net* payload margin, so a share may exceed 100% when losses on other files offset the top gains.
