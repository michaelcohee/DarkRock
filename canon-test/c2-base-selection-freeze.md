# C2 base-selection experiment: frozen rules

Freeze this document, `run_c2_base_selection.py`, the existing corpus generator, and `cad_file_keys.rs` in one commit **before** generating `darkrock-cad-dxf-v3 --split test`. The four arms run in mode Z with one complete serialized ledger per arm, each protected by RedTail-X variable-tail 4+2 and the charged manifest catalog/bootstrap. The new Tier A test split is generated, verified, and compared in one invocation. The 47 already-converted Tier B DXFs are a separate table.

1. **Processing order:** sort the manifest paths lexicographically. Only earlier *unique stored files* may be bases; SHA-256 plus byte equality makes exact duplicates back-references. No patch chains need an external source: decoding resolves a base from an earlier recovered file.
2. **C2-0:** store each unique file with standalone `zstd -3`; no patch candidates.
3. **C2-name:** first earlier unique file with the same declared family is the sole base. Tier A's generated manifest family is an oracle; Tier B uses the already-declared filename-prefix families from `tierb-dxf-controls.py`. Choose its patch only when strictly smaller than standalone zstd.
4. **C2-sketch:** FastCDC 1.7.0, min/average/max 4/16/64 KiB, per-file reset. Rank earlier unique files by descending count of *distinct shared SHA-256 chunk hashes*, with path-order ties. Try the first three candidates with positive overlap, once each.
5. **C2-key:** use the frozen A3 v2 `geometry_keys` scanner, reduced to a file-level set. Rank earlier unique files by descending count of shared distinct keys, path-order ties. Try the first three candidates with positive overlap, once each. A key is a candidate hint, never a merge rule.
6. **C2-name+key:** use C2-name when a named earlier base exists; otherwise use C2-key's three-candidate rule. C2-name's first-base rule has no ties, so this is the specified orphan case.

For sketch/key candidates, choose the smallest **verified** `zstd --patch-from` payload. Accept it only if at least 1,024 bytes smaller than standalone zstd; otherwise store the standalone frame. Named candidates use the existing C2 rule of any strict saving. Every patch attempt must decode with its proposed base to the exact original bytes and SHA-256; any failed attempt is counted as a miss. The complete coded ledger must decode from recovered shares and pass every one- and two-share-loss pattern. A failure of the final ledger invalidates the cell.

The ledger stores each filename, original length/hash, representation tag, earlier base reference, payload length and payload. Exact duplicates have a reference and no payload. There is no omitted/rebuildable candidate index in the Protected number. Candidate feature sets are measurement-time hints and not needed to restore; their memory and compute cost are reported as a limitation, not included in protected bytes. `canon_full_ledger_measure` supplies the shared 4+2 physical-byte and share-loss accounting.

Report protected bytes, patch-hit mean size, fallback rate among unique files with at least one eligible candidate, different selected base from C2-name (including one arm falling back), verify-failure counts, and harm rate. **Harm rate** is the number of files for which an arm accepts a patch larger than the C2-name patch for that same file, divided by files where both arms accept patches. Also report this numerator and denominator. The pass condition for C2-key is fewer Protected bytes than both C2-sketch and C2-0, 100% exact restore, and a reported harm rate. A tie with sketch rejects the key.
